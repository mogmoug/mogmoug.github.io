准备好了吗？ 我们从最根本的问题开始：为什么长上下文模型越来越难部署？
Q01

为什么长上下文模型越来越难部署？

💭
模型参数没变，序列变长了，成本会等比例上升吗？如果不是，瓶颈最先出现在哪里——算力、显存，还是别的地方？
解析

∑计算

稀疏注意力已大幅降低长序列计算成本，但每次 KV Cache 未命中仍需重新 Prefill。Agent 频繁工具调用持续产生新 Prefill 请求。

▣存储

Global KV 常驻 HBM，受显存约束；为前缀复用而持久化的 KV 受 SSD 与主机内存约束。

⇄带宽

I/O 与互连带宽限制缓存的迁移与加载。容量够用但搬运不及时，同样拖垮吞吐。

三者叠加 → 限制吞吐、推高成本、阻碍 Agent 向更长任务跨度扩展。既然瓶颈在缓存，那就要先搞清楚：KV Cache 到底是什么？
Q02

KV Cache 到底是什么？为什么它这么大？

💭
自回归生成时，每生成一个新 token，都要和前面所有 token 做注意力。如果每次都重新计算前面 token 的 K 和 V，会浪费什么？
解析

◧缓存的本质

把历史 token 的 Key 和 Value 缓存下来，生成新 token 时直接复用，避免重复计算。这是自回归生成的标准优化。

但缓存大小 随序列长度线性增长，且要在每层、每个注意力头都存一份。

◈两类 KV 的不同命运

  • Global KV：覆盖全上下文，序列越长越大，常驻 HBM
  • SWA KV：滑动窗口局部注意力，窗口固定则大小有界
  • 足够长的序列下，Global KV 主导运行期 KV 占用
  • 持久化 KV 则受 SSD 与主机内存约束
所以压缩的关键在 Global KV。但为什么已有的稀疏注意力还不够？下一问揭晓。
Q03

为什么稀疏注意力还不够？

💭
稀疏注意力减少了「算多少」，但它减少了「存多少」吗？两者是一回事吗？
解析

✕算得少 ≠ 存得少

稀疏注意力让每个 query 只关注部分 KV，降低了注意力计算量。但被跳过的 KV 仍然需要被存储、被索引、被搬运。

当计算不再是瓶颈，持久化存储与数据移动就浮出水面。

▤DeepSeek-V4 的混合结构

  • 全局注意力分支 + 局部 SWA 分支
  • 全局分支维护 main KV 与 indexer K
  • SWA 维护局部 KV，固定窗口下有界
  • 长序列下全局 KV 主导运行期占用
既然要压缩，就得先知道能从哪里压。KV Cache 的压缩空间有三个乘性维度。
Q04

压缩 KV Cache，有哪三个乘性维度？

💭
一个 KV 缓存条目，可以从「每个条目多大」「多少个条目」「多少层各存一份」三个方向压缩。三者是相加还是相乘？
解析

①条目大小

GQA 减少 KV 头数量；MLA 让所有头共享一个小型 latent 表示。

头维度

②序列维度

每 m 个 token 压缩成一个条目，如 DeepSeek-V4 中的 CSA 与 HCA。

长度维度

③层维度

某些层复用其他层的缓存与选择结果，或干脆被更高效的层替代。

深度维度

三者相乘，才是真正的压缩空间。那么问题来了：之前的工作覆盖了哪几个维度？
Q05

之前的工作，缺了哪一块？

💭
IndexCache 复用索引、YOIO 共享路由、HySparse 复用稠密层 KV。它们各自解决了什么？有没有共同缺口？
解析
方法做法局限
IndexCache跨层复用 Top-K 索引不节省主 KV 存储
YOIO全局共享一次稀疏路由限制性能上限
HySparse稀疏层复用稠密层 KV仍保留完整注意力层

★共同缺口

它们都没有同时覆盖三个维度。索引复用不省主 KV 存储；路由共享限制性能；混合设计仍保留全注意力层。

这正是 CSA2 要解决的问题。但在讲 CSA2 之前，先看一个更反直觉的设计：为什么 552B 的模型 Prefill 只激活 8B？
Q06

552B 的模型，为什么 Prefill 只激活 8B？

💭
Decode 激活 16B，Prefill 却只要 8B。少掉的那一半计算，被什么架构省掉了？
解析
解码器 · 20 层全局 KV 由 HL/2 投影得到
CSA2 · m = 1
↑ 投影 ↑
因果编码器 · 20 层CSA2 (m = 2) + 前 2 层 SWA
HL/2 输出

★CED 的核心思想

把 Transformer 分成上下两半：下半是因果编码器，上半是解码器。解码器的全局 KV 不再由自己的隐藏状态生成，而是直接从编码器最后一层 HL/2 用各层独立的投影权重投影而来。

∑收益

Prefill 阶段只需计算前一半层，就能获得上层的全局 KV Cache。

这个设计省了计算，但 SWA 仍逐层计算——代价是什么？ 我们稍后回答。先看公式。
Q07

CED 的公式，怎么理解？

💭
解码器第 l 层的 KV，不是从第 l 层的隐藏状态算的，而是从第 L/2 层投影的。这意味着什么？
解析
Cl = HL/2 · WlKV
Zl = HL/2 · WlZ    ( l > L/2 )

◧Cl 与 Zl

C 是 KV 条目，Z 是对应的压缩权重。两者都由同一个 HL/2 投影，只是投影矩阵逐层不同。

∑复杂度变化

序列长度 N ≫ nwin 时，Prefill 从 O(NL) 降到 O(NL/2 + nwin·L/2) ≈ O(NL/2)，整体计算近乎减半。

⚠SWA 保持逐层

SWA 的局部 KV 仍由每层自己的隐藏状态生成，以维持局部 KV 的生成深度。这带来了重放需求。

省了计算，但 SWA 逐层计算意味着解码器需要额外处理 nwin × L/2 个 token。这个代价怎么消化？
Q08

CED 省了计算，代价是什么？

💭
解码器 SWA KV 需要由各层自己的隐藏状态生成，但 Prefill 只算到编码器结束。缺失的 SWA KV 从哪来？
解析

✕精确重建的代价

SWA 依赖跨层累积。精确重建 L 层的 SWA KV，需要重放 L × nwin 个 token，在生产环境中成本不可接受。

✓但先验知识救了它

已有工作表明，SWA 的实际有效感受野远小于理论值 nwin × L/2。这为近似重建提供了依据。

于是引出 SWA Bounded Replay——只重放最近 nwin 个 token。

这个策略同时用于编码器和解码器，效果不同，我们后面专门讲。现在先转向另一个核心：CSA2 的三种模式。
Q09

CSA2 的三种模式，分别解决什么问题？

💭
三种模式都计算自己的 main Q 和 SWA KV。区别在于：main KV、indexer K、Top-K 索引，这三样东西各自是「自己算」还是「复用别人」？
解析

FFull 模式

自算 main KV 与 indexer Q，从 main KV 投影 indexer K，运行索引器产生全新 Top-K。执行完整 CSA2 路径。

缓存新建索引新建

RReindex 模式

复用最近可用的 main KV 与其 indexer K，但用自己的 indexer Q 重新打分，产生新 Top-K。

缓存复用索引新建

↺Reuse 模式

同时复用 main KV 与最近一次 Full/Reindex 算出的 Top-K，直接做稀疏注意力，不计算 indexer Q，不评估索引分数。

缓存复用索引复用
共享 main KV 与 indexer K 减少缓存存储；复用 Top-K 索引避免额外索引计算。Reindex 则在共享缓存的前提下，让选择仍能跨层变化。
Q10

三种模式怎么分配到 40 层里？

💭
如果每层都是 Full，就没有共享收益；如果每层都 Reuse，选择就无法变化。怎么分组最合理？
解析

▤编码器：3 组 × 6 层

  • 前 2 层用纯 SWA（窗口 128）
  • 其余 18 层 CSA2，压缩率 m = 2
  • 每组第 1 层 Full，其余 5 层 Reuse
  • 即每组只有 1 层产生新缓存与新索引

▤解码器：5 组 × 4 层

  • 20 层 CSA2，压缩率 m = 1
  • 首组：1 Full + 3 Reuse
  • 其余 4 组：1 Reindex + 3 Reuse
  • 解码器首个 Full 层的全局 KV 直接由编码器末层投影

★统一配置

所有 CSA2 层：indexer query 头数 32，indexer 头维度 128，稀疏注意力 Top-K = 512；query 头数 64，头维度 512，query 压缩维度 1280；输出投影 8 组，中间维度 1024。

但即使 Reuse 层不做索引，剩下的索引器仍要扫描全上下文。超长上下文下这依然是瓶颈。
Q11

分层稀疏索引器：如何让深层索引成本与长度无关？

💭
如果每个 Reindex 层都要给每个 query 扫描全部因果可见的 KV 位置，上下文越长，索引成本越高。有没有办法让浅层的选择结果帮到深层？
解析
首个 Full 层
→
扫描全部可见 KV
→
选自身 Top-512
→
构建 block 候选池
→
后续层只在池内搜索

▦候选池怎么来

每个 block 取块内最大索引分数，选出得分最高的若干 block，再把这些 block 覆盖的位置收集成候选池。

2048 blocks × 8 位置 = 16,384 候选位置

◎池共享，选择独立

候选池在所有索引层间共享，但每层最终 Top-K 选择仍可不同。Reuse 层完全不做新索引，沿用最近一次 Top-K。

∑复杂度收益

对固定候选池大小，后续每个索引器每 query 打分位置数与上下文长度无关。首个 Full 层仍需全量扫描一次。

这里有个容易混淆的点：候选池和最终 Top-K 是两个不同的东西。下一问专门辨析。
Q12

候选池和最终 Top-K，有什么区别？

💭
如果候选池直接就是最终选择，那深层索引器还有什么用？为什么要设两层？
解析

①候选池 = 搜索范围

  • 由首个 Full 层构建，粒度是 block
  • 作用是限制后续索引器在哪里搜索
  • 池子比最终选择大，留出选择余地
  • 例：16,384 个候选位置

②最终 Top-K = 实际读取

  • 由每层索引器在池内打分后选出，粒度是 token
  • 决定该层实际读取哪些 main KV 条目
  • 不同层可以选择不同的 Top-K
  • 每层 Top-K = 512

★为什么要这样设计

池共享降低了搜索成本，选择独立保留了层间表达能力。训练与推理时，候选限制的应用方式完全一致——深层索引器是在与推理相同的搜索域下被优化的，而不是事后打补丁。

架构讲完了，接下来是精度：FP4 真的能用在 KV 缓存上吗？
Q13

FP4 用在 KV 缓存上，不会掉精度吗？

💭
4-bit 听起来很激进。但如果 FP4 只用来省存储、不用来加速矩阵乘，是否就不需要硬件原生支持？
解析

▣用途不同，要求不同

这里 FP4 的目标是压缩存储体积，不是加速矩阵乘法。缓存值在注意力计算前先反量化，因此可以使用更精确的格式，而不需要硬件原生支持该格式的矩阵乘。

✓训练侧配合

在后训练阶段引入 量化感知训练（QAT），让模型在训练时就适应 FP4 缓存。非 RoPE 与 RoPE 分量使用相同量化格式。

DeepSeek-V4 已对 FP4 indexer Q/K 使用 QAT，这次扩展到 main KV。

◑SWA KV 保持 FP8

滑动窗口 KV 对量化更敏感，因此保留 FP8 精度，不参与 FP4 压缩。

选哪种 4-bit 格式？为什么可以省略全局 scale？下一问用数值说话。
Q14

为什么可以省略全局 scale？

💭
NVFP4 有二级全局 scale，这里省掉了。省略的前提是数值范围足够——KV 缓存的数值到底有多大？
解析

▣格式选择

  • 采用 OCP 标准 MXFP4，最大化硬件兼容性
  • 选定 E2M1，每 16 通道配一个 E4M3 scale
  • 参照 NVFP4 但省略二级全局 scale

◷量化位置

在 RoPE 之后量化。实验显示 RoPE 前量化只带来边际精度提升，却会在解码时引入额外开销。

∑数值范围论证

  • 格式可表示幅值上限约 448 × 6 = 2688
  • 训练中最大 RMSNorm 权重幅值约 1
  • RMS 归一化后 512 通道 KV latent 的 L2 范数至多约 √512 ≈ 22.6
  • RoPE 保持范数不变，训练观测最大幅值约 10
  • 结论：省略全局 scale 不造成可测精度下降
精度问题解决，存储几乎减半。接下来是部署层的关键一问：SWA KV 为什么不该持久化？
Q15

SWA KV 为什么不该持久化？

💭
持久化缓存的设计寿命是 72 小时，但 SWA KV 实际被复用的时间窗口有多长？这两者匹配吗？
解析

✕访问模式不匹配

  • 全局 KV 有长尾复用特征，值得长期保留
  • SWA KV 只在活跃会话内的分钟级窄窗口被复用
  • 会话结束或下一轮开始后，SWA KV 即失效
  • 为它配置 72 小时持久化，容量浪费严重

✓新方案

  • SWA KV 不再进入持久化缓存
  • 改放每台机器 10% 主机 DRAM 组成的分布式内存池
  • 池容量小，但 TTL 只有分钟级，过期立即回收
  • 全局 KV 仍在持久化缓存中，保证至少 72 小时生命周期

↺代价与兜底

驱逐 SWA KV 必然带来 miss。但凭借轻量级兜底——Encoder SWA Bounded Replay——把灾难性 miss 转化为优雅降级：只重算 nwin 个 token，而非完整的 L × nwin 前向。

那么，「有界」到底界在哪里？
Q16

有界重放，「界」在哪里？

💭
精确重建需要重放 L × nwin 个 token，有界重放只重放 nwin 个。少了 L 倍，近似程度如何？
解析

✕精确重建

SWA 依赖跨层累积，精确重建 L 层 SWA KV 需要重放 L × nwin 个 token。

✓有界重放

只重放最近 nwin 个 token，并把 SWA 截断到重放片段内。

对从位置 s 开始的重放，位置 i 的 query 只关注 [max(s, i−W+1), i] 内的 SWA key。

★效果

重放前缀状态是近似的，后续计算得到的全局 KV 与 SWA KV 依赖命中位置，不严格等价。

但实验证实：对响应质量影响几乎可忽略。

⚠训练感知适配

为稳妥起见，后训练阶段会模拟同样的重放过程，让模型提前适应这种近似状态。

有界重放在编码器和解码器上的作用不同，下一问分别拆解。
Q17

编码器重放和解码器重放，有什么不同？

💭
同一个「有界重放」策略，用在编码器和解码器上，目标分别是解决什么？
解析

E编码器侧重放

目标：让前缀缓存只依赖全局 KV。

编码器 SWA KV 缺失时，重放已缓存前缀的最后 nwin 个 token，与未缓存后缀一起处理。重放 token 只重建 SWA KV，复用已缓存的全局 KV，不重算也不覆写。这让 SWA KV 得以从持久化缓存中移除。

D解码器侧重放

目标：让 prefill 在编码器处结束。

CED 下解码器全局 KV 由编码器末层投影而来，唯一阻碍 prefill 在编码器结束的就是解码器 SWA KV。有界重放让 prefill 只处理最后 nwin 个 token，使总 prefill 计算近乎减半。重建的 SWA KV 只用于解码，不用于前缀缓存。

★共同结果

持久化 KV Cache 占用进一步降到 DeepSeek-V4-Flash 的约 1/8，同时大幅缓解 HBM 与 SSD 容量压力。

架构层面还有三个扩展件。先看最基础的：mHC 为什么要 Single-Pass？
Q18

mHC 为什么要 Single-Pass？

💭
mHC 维护 n 条残差流。原实现有多个 kernel 串行执行，各自读写一遍残差。激活内存流量的理论下界是多少？实际又是多少？
解析

✕原版多 kernel 的问题

  • 残差更新、系数预测、输入混合三个 kernel 因数据依赖串行
  • 总激活内存流量 (4n + 4)d
  • 理论下界只有 (2n + 2)d
  • 实际是下界的两倍

✓Single-Pass 的关键改动

把输入混合系数整体后移一个 block：每个 block 使用上一个 block 产生的系数。

依赖消失后，每个 tile 可以立即同时用于输入混合与系数预测，无需等待全量归约完成。

⚡Mega-mHC 部署 kernel

把残差更新、输入混合、系数预测融合为单个 kernel，同时包含输入 pre-norm 与 FP8 转换。残差只读一次写一次，激活内存流量从 (4n+4)d 降到 (2n+2)d，减半并逼近理论下界。预训练阶段仍保留多 kernel 实现，因为该改动只影响每个 block 应用哪组系数。

第二个扩展件：Engram 解决的是什么问题？
Q19

Engram 解决的是什么问题？

💭
模型里的「记忆」和「计算」一定要绑在一起吗？能不能把记忆做成稀疏查找，用查表代替一部分计算？
解析

◫条件记忆模块

把「记忆」与「计算」解耦的稀疏条件记忆模块，共 196B 参数，均分到两个模块。

  • N-gram 阶数 {2, 3, 4}
  • 每阶 8 个 hash head，嵌入维度 2048
  • 每张表约 1600 万条目，表长取不同素数
  • 嵌入表与投影均为 FP8
  • 放置在第 1 与第 14 层，平衡流水线显存

⚙推理侧优化

  • 确定性寻址，嵌入可从主机内存通过后台 RDMA 预取
  • 第一个模块的预取与第一个 Transformer block 的计算重叠
  • RL rollout 期间嵌入表常驻 GPU 显存，减少主机内存压力
  • 嵌入以 FP8 存储与获取，检索值直接送入后续 GEMM

◈优化器配合

嵌入表、token embedding、预测头使用动量 + Sinkhorn 平衡更新替代 Adam，只需一份动量缓冲，大幅降低优化器状态显存。

DSpark 如何加速解码？

💭

解析

①半自回归草稿

3 个 Transformer block，滑动窗口 128。一次前向并行计算 5 个草稿位置的基础 logits，轻量 Markov 头建模草稿间依赖。

②置信度调度验证

Q24

百万级并发沙箱，如何管理？

💭
Kubernetes 依赖中心化的强一致性调度。当容器数量达到百万级，中心协调会不会成为瓶颈？能不能用「最终一致性」换扩展性？
解析

▤DSec 的设计取舍

  • 分片：计算节点划分为多个 scale unit，隔离不同实验，缩小爆炸半径
  • 自定义放置引擎：多副本独立运行，不做同步协调，各副本根据近期测量预测资源并做「足够好」的决策
  • 节点兜底：每个节点验证最终放置决策，超过本地警戒阈值就拒绝新放置
  • 用最终一致性 + 本地硬约束替代全局强一致性

⚙高密度与干扰控制

  • 硬件支持的 sub-NUMA 分区，每个 worker VM 绑定独立 NUMA 域
  • 单机容器密度从约 1000 提升到 2500+
  • 引入延迟敏感（LS）执行类，非 LS 任务用 SCHED_IDLE 降低优先级
  • 核心调度确保同优先级任务才在兄弟超线程上同时执行

⚠遏制越界行为

RL 训练中常见 Agent 尝试奖励黑客或意外崩溃环境，甚至利用已披露漏洞、删除关键二进制或文件系统。DSec 用每沙箱 AppArmor 配置与细粒度 eBPF 网络策略拦截；若 Agent 崩溃环境，视为失败轨迹并向 RL 框架上报「反噬」信号。

Q25

异步 RL 有什么副作用？怎么缓解？

💭
异步生成提高了 rollout 效率，但样本可能由旧 checkpoint 生成，且短序列先完成。这两件事分别会带来什么问题？
解析

⚠副作用一：长度偏置

短序列先完成，在训练早期主导初始批次。

  • 数据集级并发限制：调节各数据集在稳态批次中的比例，间接缓解长度偏斜
  • 丢弃过早返回的短样本：平滑过渡到稳态长度分布，防止过拟合短序列

⚠副作用二：Off-policy

样本的 token 部分或全部由更早的 checkpoint 生成。

  • 限制最大 off-policy 比例：通过派发逻辑与等待条件控制
  • 损失掩码：消除过时 token 的贡献，减轻陈旧样本对梯度更新的影响

★无缝中断与恢复

支持 token 级中断；KV Cache 与专家路由按 token 粒度持久化，切换 checkpoint 后直接复用，免除重新 prefill。同一机制也让训练任务迅速响应集群抢占信号而不丢进度。

Q27

为什么惩罚系数要指数衰减？

💭
如果推理的边际收益随长度递减，那么最优长度和努力度之间应该是什么关系？线性？指数？还是别的？
解析
rlenb,j = −min{ Cmax , k(b) · ℓb,j / Lnorm }

k(b) = k0 · exp( −(b − bmin) / τ )
τ = λ · Δb̄
  • k₀：最低努力度下的惩罚系数，控制整体收缩压力
  • τ：惩罚衰减速率，控制对努力度的敏感度
  • 努力度增加 τ，惩罚系数乘以 e⁻¹

∑推导直觉

假设解题概率的边际收益随长度近似指数衰减：

p'(ℓ) ≈ ax · exp(−ℓ/sx)

在内部最优解处，边际收益等于边际惩罚，可得最优长度与努力度呈一阶仿射关系：

ℓ*(b) ≈ Cx − sx·log k0 + (sx/τ)·(b − bmin)

⚠这是局部近似

真实行为可能偏离：努力度指令会改变推理策略、生成具有随机性、Agent 轨迹包含不同轮数、子组奖励归一化改变优化强度。该分析假设惩罚上限未激活；一旦触顶，边际惩罚为零，需单独考虑。

RECAP

从问题到答案：完整逻辑链

①问题层

  • 长上下文部署受计算、存储、带宽三重约束
  • 稀疏注意力降低了计算，但存储与搬运成为新瓶颈
  • KV 压缩有条目大小、序列、层三个乘性维度，已有工作未同时覆盖

②架构层

  • CED：解码器全局 KV 从编码器末层投影，Prefill 只算一半层
  • CSA2：Full/Reindex/Reuse 三模式，跨层共享 main KV 与 indexer K
  • 分层稀疏索引器：候选池共享，深层索引成本与长度解耦
  • FP4 KV：反量化后注意力，省略全局 scale

③部署层

  • SWA Bounded Replay：只重放 nwin 个 token
  • 编码器重放 → 移除 SWA 持久化；解码器重放 → Prefill 减半
  • 持久化 KV 降到 V4 的约 1/8

④训练层

  • 45T 多模态语料，从零训练稀疏注意力，无稠密预热
  • 后训练无算法创新，收益来自数据与环境管线
  • DSec 百万级沙箱，异步 RL 的偏置与 off-policy 有对应缓解
  • 标量努力度 b 提供可控的成本-质量权衡
一句话总结：通过架构、精度与部署的联合优化，在压缩 KV Cache 到极限的同时，把性能推到了开源模型前列。
SUMMARY

如果只能记住五句话

1瓶颈转移

稀疏注意力解决「算得少」，但没解决「存得少、搬得快」。长上下文部署的真正瓶颈已转向存储与带宽。

2CED 的非对称激活

解码器全局 KV 由编码器末层投影，Prefill 只需算前一半层，激活 8B；Decode 才需要完整 16B。输入密集型 Agent 负载因此显著受益。

3CSA2 的三维联合压缩

同时利用条目、序列、层三个维度：跨层共享 main KV 与 indexer K，复用 Top-K 索引，再用分层索引器把深层搜索域限制在候选池内。

4有界重放的新权衡

用少量 Prefill 重算换取 SWA KV 不再持久化。持久化 KV 降到约 1/8，而重放只处理 nwin 个 token，性能影响可忽略。

5数据与环境 > 算法创新

后训练流程标准，收益几乎全部来自合成数据与环境的规模、多样性与可验证性。这是当前阶段值得记住的工程结论。

  • 持久化 KV：约为 V4-Flash 的 1/8

  • 候选池：2048 blocks × 8 位置 = 16,384
  • indexer 头数 32，头维度 128
  • Reuse 层：Prefill 15 kernel，Decode 11 kernel
